# برنامهٔ نیتیو AsoTas (Rust + Kotlin/Compose)

بازنویسی برنامهٔ اندروید AsoTas از پایه، به جای صفحه‌های وب داخل Capacitor (`game_club/android-app`).
سرور همان سرور فعلی است و تغییری نمی‌کند؛ برنامه فقط داده را از API مینی اپ (`/gc/api/*`) می‌گیرد.

| بخش | زبان | کجا |
|---|---|---|
| گفتگو با سرور، ورود، توکن، (بعدا) کش و فیزیک و قوانین بازی‌ها | **Rust** | `crates/asotas-core` |
| صفحه‌ها، فرم‌ها، رسم بازی‌ها | **Kotlin + Jetpack Compose** | `android/` |
| اتصال این دو | **UniFFI** (کد کاتلین خودکار ساخته می‌شود) | `crates/uniffi-bindgen` |

## چه چیزهایی آماده است (مرحلهٔ ۱)

- **حساب مهمان**: بار اول `POST /gc/app/guest` و توکن نشست در پوشهٔ خصوصی برنامه؛ اگر سرور ۴۰۱ داد
  یک حساب مهمان تازه و همان درخواست یک بار دیگر (مثل `static/app.js`).
- **ورود با تلگرام** (لینک ربات، هر ۲ ثانیه پرسیدن نتیجه) و **ورود با ایمیل** (کد ۶ رقمی، شمارش معکوس
  «دوباره بفرست»). برگهٔ «خوش اومدی» بار اول، با «فعلاً مهمون می‌مونم».
- **خانه**: یوزرنیم، سکه، تعداد بازی و برد، پیام تعمیرات و اطلاعیه، **جایزهٔ روزانه**، کاشی ۸ بازی
  (فعلاً «به‌زودی»)، وضعیت حساب و خروج.
- کل برنامه راست‌به‌چپ است؛ فیلد ایمیل و کد چپ‌به‌چپ. رقم فارسی هم در کد ورود قبول می‌شود.

## داده‌ها کجا می‌مانند

- **سرور (منبع اصلی)**: حساب، سکه، امتیاز، نتیجهٔ بازی‌ها. برنامه سکه را خودش حساب نمی‌کند.
- **گوشی**: فقط توکن نشست (`noBackupFilesDir/session.json`، در پشتیبان گیری گوگل نمی‌رود).
  بعدا: کش پروفایل و رفقا و چت (SQLite) تا برنامه سریع باز شود.

## ساختن

**روی GitHub** (روش اصلی): workflow «AsoTas Native» با هر push که `native-app/` را عوض کند
تست‌های Rust و APK آزمایشی را می‌سازد؛ از صفحهٔ Actions دانلودش کن. با Run workflow و شماره نسخه،
اگر Secrets کلید امضا (همان `GC_KEYSTORE_*` برنامهٔ فعلی) باشد APK امضاشدهٔ انتشار هم ساخته می‌شود.

**روی کامپیوتر خودت** فقط هستهٔ Rust تست می‌شود (ابزار اندروید لازم نیست). روی ویندوز، Rust به بخش
C++ ویژوال استودیو (Desktop development with C++) نیاز دارد؛ بدون آن تست‌ها فقط روی GitHub اجرا می‌شوند.

```bash
cd native-app
cargo test
```

## نام بسته

- انتشار: `dezhcode.AsoTas.app` (بعد از اولین انتشار در مایکت عوض نمی‌شود).
  برنامهٔ Capacitor (`game_club/android-app`) هم همین نام بسته، همین فایربیس و همین کلید امضا را دارد، پس در مایکت
  یک برنامه‌اند و هر کدام منتشر شود جای دیگری را می‌گیرد (`version_code` باید از هر دو بیشتر باشد).
- آزمایشی: `dezhcode.AsoTas.app.dev`، کنار نسخهٔ انتشار نصب می‌شود.
- کد کاتلین در پکیج `dezhcode.asotas` است (با حروف کوچک، طبق قرارداد کاتلین)؛ ربطی به نام بسته ندارد.

## قدم‌های بعد

1. بیلیارد: فیزیک در Rust (از `static/billiard-engine.js`) با تست، رسم در Compose Canvas، بازی با ربات و آنلاین
2. رفقا و چت، پروفایل، رده‌بندی، فروشگاه ظاهر
3. بقیهٔ بازی‌ها
4. فونت‌های Peyda و Rokh (الان فونت خود گوشی)، عکس پروفایل، صدا

نکته: برنامهٔ Capacitor صفحه‌ها را خودکار از سرور آپدیت می‌کرد. برنامهٔ نیتیو این را ندارد و
هر تغییر رابط کاربری یعنی یک نسخهٔ تازه در مایکت.
